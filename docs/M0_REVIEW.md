## التبعيات المثبتة من المصدر

تم جلب المصدر الرسمي وفحص `__manifest__.py` عند
`9cd6f090a8a21d9531c70ceec7f5c51271e24168`؛ لا تعديلات على Odoo Core.
جميع الوحدات التالية موجودة وترخيصها `LGPL-3` في هذا المصدر.

| المجال | الوحدات | النتيجة وحدودها |
|---|---|---|
| المتجر | website_sale, sale_management, delivery, payment | أساس المنتجات والطلبات والتوصيل والدفع؛ يلزم E2E للدفع عند الاستلام والتحويل |
| الفوترة | account, account_payment | `account` اسمه Invoicing؛ `account_payment` دفع الفواتير عبر البوابة؛ لا يثبت اكتمال Accounting Enterprise |
| الشراء | purchase, purchase_stock | أساس أمر الشراء وفاتورة المورد والاستلام |
| المخزون | stock, stock_account | أساس الحركات والتقييم؛ السياسات والتقارير تحتاج اختبارًا |
| التواصل | mail, portal | مراسلات وبوابة قياسية؛ لا تعني تكامل WhatsApp رسميًا جاهزًا |

`base.YER` موجود في بيانات `res.currency`؛ لم تُعتمد أسعار صرف أو ضرائب أو
سياسات محاسبية يمنية. `addons/l10n_ye` **غير موجود** في المصدر المثبت.
لم تُضف إضافات Enterprise أو طرف ثالث. كود الـProvisioner يستخدم Python stdlib؛
التشفير يستخدم GnuPG المتاح على مضيف الاختبار. في متابعة PR #4 ثُبّتت digests لصور الأساس، ونجح فحص صور التشغيل الفعلية
والشيفرة وتاريخ Git عند `f1ae638` دون استثناءات HIGH/CRITICAL. البناء والنشر
بنفس digest ومراجعة الاختراق والتحديث المستمر تبقى شروطًا للإنتاج؛ نجاح الفحص
ليس شهادة أمان شاملة.

## قرار تجربة M2

- SQLite مخصص لسجل تهيئة محلي فقط، ولا يحتوي معاملات أو أرصدة المتجر.
- عامل واحد محلي بقفل OS ومعاملة unique للمفتاح وslug؛ المفتاح مخزن كـSHA-256.
- لكل متجر مشروع Compose مستقل وحاوية PostgreSQL وشبكتان داخليتان وFilestore مستقل.
- مستخدم DB محدود ليس superuser ولا مالك قاعدة البيانات؛ صلاحية إنشاء جداول في
  schema الخاصة بقاعدة متجره ضرورية لتثبيت Odoo. يحتاج Odoo 19 صلاحية CONNECT
  فقط لقاعدة `postgres` الفارغة داخل حاوية متجره لفحص الكتالوج عند بدء التشغيل؛
  لا TEMP/CREATEDB ولا وصول لبيانات متجر آخر.
- الـRuntime لا يرى مجلد المشروع كله أو سجل المشغّل أو أسرار متجر آخر.
- `db_name` يحتوي اسم قاعدة واحدة ثابتة و`dbfilter` فارغ عمدًا: مصدر Odoo 19
  في `service/db.py:list_dbs` يستخدم قائمة `db_name` مباشرة في هذه الحالة،
  و`http.py:db_filter` يرفض أسماء القواعد خارجها. وضع regex مع مستخدم ليس مالكًا
  يعيد قائمة فارغة من استعلام الملكية ويعطّل اكتشاف قاعدة HTTP. لا نغيّر Core
  ولا نجعل مستخدم التطبيق مالكًا للقاعدة لحل ذلك.
- نطاقات اختبار `<slug>.nasqo.test`؛ Nginx يقبل قائمة نطاقات المتاجر الناجحة فقط.
  الطلبات غير المعروفة تُرفض بـ421، وتُحجب إدارة قواعد البيانات وlegacy RPC.
- استعادة النسخ إلى مشروع جديد بنفس هوية التاجر؛ لا مسار للكتابة فوق متجر قائم.
- لا منفذ للمستأجر أو PostgreSQL على المضيف. المنفذ الوحيد للبوابة `127.0.0.1:18069`.
  البوابة وحدها ترتبط بشبكة `edge` عادية لنشر المنفذ؛ تبقى شبكات Odoo/PostgreSQL
  داخلية. يتحقق التشغيل من وصول المضيف ورفض Host غير معروف قبل إعلان جاهزيتها.
- القرار **تجريبي**. لا API تجاري، تسجيل، MFA، Queue موزع، TLS عام، أو ضمان SLA.

## بوابات لم تُعتمد بعد

مالك الأمن والمراجعة المالية، سياسة «له/عليه»، العملة الأساسية وسعر الصرف،
التوطين والضرائب، حدود الباقات، مزود الدفع، سياسة الاحتفاظ وRPO/RTO، وبنية
التحكم التجارية. لا يمنع غياب هذه القرارات إجراء الاختبارات الاصطناعية المعزولة؛
يمنع إعلان الجاهزية التجارية والمالية.
